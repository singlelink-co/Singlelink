<h2 id="features">✨ Features</h2>

*   **User Authentication:** Secure sign-up and login functionality.
*   **Link Management:** Easily add, edit, delete, and reorder your links.
*   **Multiple Link Types:**
    *   Standard links (vanilla)
    *   Text blocks
    *   Avatar display
    *   **Premium:** YouTube video embeds, Image links, Custom HTML embeds.
*   **Subscription Tiers:**
    *   **Free Plan:** Access to basic link types and analytics.
    *   **Pro Plan:** Unlocks premium link types and advanced analytics.
    *   **Business Plan:** All Pro features plus benefits for larger needs (conceptual: team members, priority support).
*   **Analytics:** Track views and clicks on your links (basic for Free, advanced for Pro/Business).
*   **Admin Panel:** Manage users and view their subscription statuses.
*   **Customization:** Control site metadata (title, description, OG image) and branding display.
*   **Docker Support:** Includes `docker-compose.yml` and `Dockerfile` for self-hosting with Docker.
*   **Database Migrations:** Uses `migrate-mysql` for managing database schema changes.
*   **Stripe Integration:** Backend setup for handling subscriptions via Stripe Checkout and webhooks.
*   **Ready for Vercel:** Optimized for deployment on Vercel with a pre-configured GitHub Actions CI/CD workflow.

<h2 id="local-development">💻 Local Development</h2>

LaunchLinks is built with Next.js, GraphQL (Apollo Server), and MySQL.

**Prerequisites:**
*   [Node.js](https://nodejs.org/) (LTS version, e.g., 18.x or 20.x)
*   [MySQL](https://www.mysql.com/) server (or Docker for MySQL, see below)
*   [Git](https://git-scm.com/)

**Setup Instructions:**

1.  **Clone the Repository:**
    ```bash
    git clone https://github.com/your-repo/launchlinks.git
    cd launchlinks
    ```
    (Replace `your-repo/launchlinks.git` with your actual repository URL)

2.  **Install Dependencies:**
    ```bash
    npm install --legacy-peer-deps
    ```
    (*`--legacy-peer-deps` is used due to some older peer dependency requirements.*)

3.  **Set Up Environment Variables:**
    *   Copy the template file:
        ```bash
        cp .env.template .env
        ```
    *   Edit the `.env` file and fill in all the required values. Refer to the comments in `.env.template` for guidance on each variable. Key variables include:
        *   Database connection details (`DB_DATABASE`, `DB_PORT`, `DB_HOST`, `DB_USER`, `DB_PASSWORD`)
        *   `NEXTAUTH_SECRET` (generate a strong secret)
        *   `NEXTAUTH_URL` (for local development, usually `http://localhost:3000`)
        *   Stripe API keys and Price IDs (if testing subscriptions)

4.  **Database Setup:**
    *   Ensure your MySQL server is running and accessible with the credentials provided in your `.env` file.
    *   To set up a MySQL instance quickly using Docker, you can use the provided script (ensure Docker is installed):
        ```bash
        npm run boot:db
        ```
        (*This will use `launchlinks` as the database name and `launchlinks-secret` as the root password by default. Adjust your `.env` accordingly or modify `package.json`.*)
    *   Run database migrations to create the necessary tables:
        ```bash
        npm run migrate
        ```
        (*You may need to run `npm run migrate` again if you pull changes that include new database migrations.*)

5.  **Start the Development Server:**
    ```bash
    npm run dev
    ```

6.  **Access LaunchLinks:**
    *   Open [http://localhost:3000](http://localhost:3000) in your browser to view your instance.
    *   Sign up for a new account at `http://localhost:3000/auth/signup`.
    *   Log in at `http://localhost:3000/auth/login`.

<h2 id="production-deployment">🚀 Production Deployment</h2>

LaunchLinks is optimized for deployment on [Vercel](https://vercel.com), the creators of Next.js.

### Automated Deployment with Vercel via GitHub Actions

This project includes a GitHub Actions workflow (`.github/workflows/deploy.yml`) that automatically builds and deploys the application to Vercel when changes are pushed to the `main` branch.

**Setup Steps:**

1.  **Fork and Clone:** Fork this repository and clone it to your local machine.
2.  **Vercel Project:**
    *   Sign up or log in to [Vercel](https://vercel.com).
    *   Create a new Vercel project and link it to your forked GitHub repository. Vercel will often auto-detect that it's a Next.js project.
3.  **Environment Variables on Vercel:**
    *   In your Vercel project settings, configure all the necessary environment variables as outlined in the `.env.template` file. This includes your database credentials, NextAuth.js settings, Stripe API keys, and Stripe Price IDs.
    *   **Important:** For `NEXTAUTH_URL`, use your production Vercel domain (e.g., `https://your-project-name.vercel.app` or your custom domain).
4.  **GitHub Repository Secrets for Vercel CLI Action:**
    *   In your GitHub repository settings (under "Secrets and variables" > "Actions"), add the following secrets. These are required by the `vercel/vercel-action` in the GitHub Actions workflow to authorize deployments to your Vercel account and project.
        *   `VERCEL_ORG_ID`: Your Vercel organization/account ID. (Find this on Vercel under Account Settings -> General -> Your Account ID, or if part of a team, the Team ID).
        *   `VERCEL_PROJECT_ID`: The ID of the Vercel project you created. (Find this in your Vercel project settings -> General -> Project ID).
        *   `VERCEL_TOKEN`: An Access Token generated from your Vercel account settings (Tokens tab).
    *   Also add any build-time environment variables needed by `npm run build` to GitHub secrets if they are not public (e.g., `NEXTAUTH_URL_PROD` if you use it in the workflow).
5.  **Database Migrations:**
    *   The GitHub Actions workflow primarily handles the frontend build and deployment. Database migrations (`npm run migrate`) need to be run against your production database. Vercel offers ways to run scripts before a deployment becomes live (e.g., using a [release phase script](https://vercel.com/docs/build-output-api/v3#vercel-primitives/release-phase) in your `vercel.json` or by manually running migrations against your production DB before or after deployment).
    *   For a simpler setup, you might run migrations manually or from your local machine targeting the production database after a successful deployment.
6.  **Push to `main`:** Once the secrets are set up, pushing to the `main` branch will trigger the GitHub Action, which will build and deploy your LaunchLinks instance to Vercel.

### Custom Domain

After deploying to Vercel, you can easily connect a custom domain through the Vercel project dashboard (Settings -> Domains).

### Manual Deployment (Alternative)

You can also deploy LaunchLinks manually using the Vercel CLI or by connecting your Git repository directly in the Vercel dashboard without using the provided GitHub Action. Refer to the [Vercel documentation](https://vercel.com/docs) for more details.
